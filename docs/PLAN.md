# แผนพัฒนา Progressive Web App: ติดตามสถานการณ์น้ำท่วม กทม. และปริมณฑล

> สถานะ: v0.2 — ปรับตามข้อสรุปกับเจ้าของโครงการ และเริ่ม MVP แล้ว (ดู `README.md`)
> รายการที่มีเครื่องหมาย **[ต้องยืนยัน]** คือสิ่งที่ต้องตรวจสอบกับแหล่งข้อมูลจริง

## 1. ข้อสรุปจากเจ้าของโครงการ

| หัวข้อ | ข้อสรุป | ผลต่อการออกแบบ |
|---|---|---|
| กลุ่มผู้ใช้ | ประชาชนทั่วไป | ภาษาไทยเป็นหลัก, ใช้งานง่ายบนมือถือ, ต้องมีข้อความว่า "ไม่ใช่ประกาศทางการ" |
| ข้อตกลงใช้ข้อมูลกับหน่วยงาน | ยังไม่มี | ใช้เฉพาะ API/ข้อมูลสาธารณะ, ไม่ scrape เว็บภาครัฐ |
| CCTV | ลิงก์ไปดูที่ระบบกล้องของ กทม. ได้ | **ไม่ต้องมี CCTV proxy / สตรีมวิดีโอ** — แสดงเป็นลิงก์ออกไปยังเว็บของหน่วยงาน |
| ประตูระบายน้ำ | ดูสถานะอย่างเดียว | ไม่มีฟังก์ชันสั่งการ, อ่านอย่างเดียว |
| งบประมาณ | ทำฟรีก่อน | ไม่มีฐานข้อมูล/Redis ใน MVP, ใช้ cache ในหน่วยความจำ, โฮสต์บนบริการ free tier |
| ภาษา backend | Node.js | Node.js + TypeScript + Hono |

## 2. แหล่งข้อมูล

| กลุ่มข้อมูล | แหล่งข้อมูล | ใช้ใน MVP | หมายเหตุ |
|---|---|---|---|
| ระดับน้ำ (คลอง/แม่น้ำ) | ThaiWater (สสน.) public API `waterlevel_load` | ✅ | **[ต้องยืนยัน]** โครงสร้าง JSON และเงื่อนไขการใช้งาน — adapter เขียนแบบยืดหยุ่นไว้แล้ว |
| ฝนสะสม 24 ชม. | ThaiWater public API `rain_24h` | ✅ | **[ต้องยืนยัน]** เช่นเดียวกัน |
| สถานะประตูระบายน้ำ | ThaiWater / กรมชลประทาน / สำนักการระบายน้ำ กทม. | ⚠️ ตั้งค่า URL ได้ (`THAIWATER_FLOODGATE_URL`) | **[ต้องยืนยัน]** ยังไม่พบ endpoint สาธารณะที่แน่ชัด — ระหว่างนี้แสดงลิงก์ไปยังเว็บหน่วยงาน |
| กล้อง CCTV | BMA Traffic (กทม.), Longdo Traffic | ✅ แบบลิงก์ | ไม่ดึงภาพมาแสดงซ้ำ จึงไม่ต้องจัดเก็บภาพ (ลดประเด็นลิขสิทธิ์/PDPA) |
| เรดาร์ฝน, พื้นที่น้ำท่วมดาวเทียม | กทม., GISTDA | ✅ แบบลิงก์ | เฟสถัดไป: ซ้อนชั้นแผนที่ WMS ของ GISTDA |

## 3. สถาปัตยกรรม (ฉบับฟรี)

```
ผู้ใช้ (มือถือ/เดสก์ท็อป)
  │
  ▼
PWA (Vite + TypeScript + Leaflet + vite-plugin-pwa)      ← โฮสต์ฟรี: GitHub Pages / Cloudflare Pages
  - แผนที่ OSM, ชั้นข้อมูล ระดับน้ำ / ฝน / ประตูระบายน้ำ
  - Service Worker: cache แอป + ข้อมูลล่าสุด (ใช้ได้ตอนออฟไลน์)
  - แท็บ "กล้อง CCTV" = ลิงก์ไปเว็บของหน่วยงาน
  │  REST (JSON)
  ▼
API (Node.js + Hono)                                     ← โฮสต์ฟรี: Render / Koyeb
  - /api/water-level  /api/rain  /api/floodgates  /api/links  /api/health
  - cache ในหน่วยความจำ 5 นาที, ส่งข้อมูลเก่า (สูงสุด 6 ชม.) พร้อมป้าย stale เมื่อต้นทางล่ม
  - กรองเฉพาะ 6 จังหวัด (กทม., นนทบุรี, ปทุมธานี, สมุทรปราการ, สมุทรสาคร, นครปฐม)
  │
  ▼
ThaiWater public API (และแหล่งอื่นในอนาคต)
```

เหตุผลที่ยังต้องมี API กลาง แม้จะอยากประหยัด: ลดจำนวนคำขอไปยังระบบของหน่วยงาน (ผู้ใช้หลายพันคนใช้ cache ชุดเดียวกัน),
แก้ปัญหา CORS, และแปลงข้อมูลเป็นรูปแบบเดียวกันก่อนส่งให้หน้าเว็บ

## 4. แผนการดำเนินงาน

| เฟส | งาน | สถานะ |
|---|---|---|
| 1. โครงพื้นฐาน + MVP | monorepo, API + adapter ThaiWater, ข้อมูลตัวอย่าง, PWA แผนที่/รายการเฝ้าระวัง/ลิงก์ CCTV, offline, เทสต์ | ✅ เสร็จ (ยังไม่ได้ทดสอบกับ API จริง) |
| 2. เชื่อมข้อมูลจริง | ทดสอบ ThaiWater API จริง, ปรับ field mapping, ขอ API key ถ้าจำเป็น | ⏭️ ถัดไป |
| 3. เผยแพร่ฟรี | Deploy หน้าเว็บ (GitHub Pages) + API (Render free), ตั้ง `CORS_ORIGIN` | |
| 4. ประตูระบายน้ำ | หาแหล่งข้อมูลสถานะประตูน้ำที่เปิดสาธารณะ / ติดต่อหน่วยงาน | |
| 5. เสริม | ชั้นแผนที่น้ำท่วม GISTDA, บันทึกจุดที่ติดตาม, กราฟย้อนหลัง, Web Push แจ้งเตือน | |

## 5. ข้อจำกัดของเวอร์ชันฟรี

- บริการฟรีบางแห่ง (เช่น Render) จะหยุดเซิร์ฟเวอร์เมื่อไม่มีการใช้งาน คำขอแรกอาจช้า 30–60 วินาที
- cache อยู่ในหน่วยความจำ เซิร์ฟเวอร์รีสตาร์ทแล้วต้องดึงใหม่
- ไม่มีข้อมูลย้อนหลัง/กราฟ จนกว่าจะเพิ่มฐานข้อมูล (ทางเลือกฟรี: Supabase / Neon free tier)
- แผนที่ฐาน OpenStreetMap มีนโยบายจำกัดการใช้งานหนัก หากผู้ใช้มากควรเปลี่ยนผู้ให้บริการ tile
- Web Push บน iOS ใช้ได้เมื่อผู้ใช้ "เพิ่มไปยังหน้าจอโฮม" เท่านั้น

## 6. เกณฑ์สถานะ (ปรับได้ใน `packages/shared/src/index.ts`)

- ระดับน้ำ (% ของระดับตลิ่ง): <70 ปกติ, 70–90 เฝ้าระวัง, 90–100 เตือนภัย, >100 วิกฤต
- ฝนสะสม 24 ชม.: ≤10 มม. ปกติ, 10–35 เฝ้าระวัง, 35–90 เตือนภัย (ฝนหนัก), >90 วิกฤต (ฝนหนักมาก)

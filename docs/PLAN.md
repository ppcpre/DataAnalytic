# แผนพัฒนา Progressive Web App: ติดตามสถานการณ์น้ำท่วม กทม. และปริมณฑล

> สถานะ: ร่างแผน (Draft v0.1) — รายการที่มีเครื่องหมาย **[ต้องยืนยัน]** คือสิ่งที่ต้องตรวจสอบกับหน่วยงานเจ้าของข้อมูลก่อนเริ่มพัฒนาจริง

## 1. เป้าหมาย

PWA ที่เปิดได้ทั้งบนมือถือและเดสก์ท็อป ติดตั้งลงหน้าจอหลักได้ ใช้งานได้แม้สัญญาณอ่อน และแสดงข้อมูล 3 กลุ่มบนแผนที่เดียวกัน:

1. **สถานการณ์น้ำท่วม** — ระดับน้ำในคลอง/แม่น้ำ ปริมาณฝน จุดน้ำท่วมขัง พื้นที่น้ำท่วมจากดาวเทียม
2. **กล้องวงจรปิด (CCTV) ตามถนน** — ภาพนิ่งล่าสุด/วิดีโอสด ณ จุดเสี่ยงน้ำท่วม
3. **ประตูระบายน้ำ / สถานีสูบน้ำ** — สถานะเปิด-ปิด ระดับน้ำหน้า-หลังประตู อัตราการสูบ

พื้นที่ครอบคลุม: กรุงเทพมหานคร, นนทบุรี, ปทุมธานี, สมุทรปราการ, สมุทรสาคร, นครปฐม

## 2. แหล่งข้อมูลที่คาดว่าจะใช้

| กลุ่มข้อมูล | แหล่งข้อมูล | รูปแบบที่คาดไว้ | หมายเหตุ |
|---|---|---|---|
| ระดับน้ำคลอง, ฝน, จุดน้ำท่วมขัง กทม. | สำนักการระบายน้ำ กทม. (ศูนย์ควบคุมระบบป้องกันน้ำท่วม) | เว็บ/API ภายใน | **[ต้องยืนยัน]** ช่องทาง API ทางการ หรือขอ MOU |
| ระดับน้ำ/ฝน/ประตูระบายน้ำ ระดับประเทศ | คลังข้อมูลน้ำแห่งชาติ ThaiWater (สสน.) | REST API (JSON) | ครอบคลุมปริมณฑล **[ต้องยืนยัน]** เงื่อนไขการใช้งานและ API key |
| ระดับน้ำเจ้าพระยา, ประตูระบายน้ำของกรมชลประทาน | กรมชลประทาน (RID) | เว็บ/API | **[ต้องยืนยัน]** |
| พยากรณ์ฝน, เรดาร์ | กรมอุตุนิยมวิทยา (TMD) | API (ต้องลงทะเบียน) / ภาพเรดาร์ | |
| พื้นที่น้ำท่วมจากดาวเทียม | GISTDA | WMS/WFS layer | ใช้เป็นชั้นแผนที่ |
| รายงานจากประชาชน | Traffy Fondue | **[ต้องยืนยัน]** | ใช้เสริมจุดน้ำท่วมขังแบบ real-time |
| ชุดข้อมูลเปิดอื่น ๆ | data.go.th | CKAN API | พิกัดประตูน้ำ/สถานีสูบ (ข้อมูลอ้างอิงคงที่) |
| CCTV ถนน กทม. | กทม. (ระบบกล้อง CCTV จราจร) | ภาพนิ่ง / สตรีม | **[ต้องยืนยัน]** สิทธิ์การนำไปแสดงผลซ้ำ |
| CCTV ทางหลวง/ปริมณฑล | กรมทางหลวง, ศูนย์ข้อมูลจราจร (เช่น Longdo Traffic / iTIC) | ภาพนิ่ง / API | **[ต้องยืนยัน]** เงื่อนไขการใช้งาน |

> ข้อควรระวัง: หลายแหล่งไม่มี API สาธารณะอย่างเป็นทางการ ควรขอความร่วมมือ/ทำหนังสือขอใช้ข้อมูลก่อน และ **หลีกเลี่ยงการ scrape เว็บไซต์ภาครัฐ** โดยไม่ได้รับอนุญาต

## 3. สถาปัตยกรรมระบบ

```
┌──────────────────────────── ผู้ใช้ (มือถือ / เดสก์ท็อป) ───────────────────────────┐
│  PWA (React + Vite + TypeScript)                                                  │
│  - แผนที่ MapLibre GL (ชั้นข้อมูล: น้ำ / CCTV / ประตูน้ำ / พื้นที่ท่วม)              │
│  - Service Worker (Workbox): cache ข้อมูลล่าสุด, offline fallback, Web Push        │
│  - IndexedDB: เก็บ snapshot ข้อมูลล่าสุด + จุดที่ผู้ใช้ติดตาม                          │
└───────────────▲──────────────────────────────▲────────────────────────────────────┘
                │ REST / SSE                   │ ภาพ CCTV (snapshot / HLS)
┌───────────────┴──────────────┐   ┌───────────┴─────────────────┐
│  API Gateway (FastAPI หรือ   │   │  CCTV Proxy                  │
│  Node.js/NestJS)             │   │  - ดึงภาพนิ่งตามรอบ + cache    │
│  - /stations /floodgates     │   │  - RTSP → HLS (MediaMTX)     │
│  - /cameras /alerts /areas   │   │    เฉพาะกล้องที่ได้รับอนุญาต   │
└───────────────▲──────────────┘   └───────────▲─────────────────┘
                │                              │
┌───────────────┴──────────────────────────────┴──────────────────┐
│  Ingestion Workers (ตั้งเวลาทุก 5–15 นาทีตามแหล่งข้อมูล)            │
│  - Adapter ต่อแหล่งข้อมูลละ 1 ตัว → แปลงเป็น schema กลาง           │
│  - ตรวจค่าเกินเกณฑ์ → สร้าง alert → ส่ง Web Push                   │
└───────────────▲─────────────────────────────────────────────────┘
                │
┌───────────────┴─────────────────────────────────────────────────┐
│  PostgreSQL + PostGIS (ข้อมูลพิกัด, ค่าวัดย้อนหลัง)                  │
│  Redis (cache ค่าล่าสุด, rate limit, queue)                         │
└─────────────────────────────────────────────────────────────────┘
```

### เหตุผลการเลือกเทคโนโลยี
- **PWA แทนแอป native**: เผยแพร่ได้ทันทีผ่าน URL ไม่ต้องผ่าน App Store รองรับ Web Push บน Android และ iOS 16.4+ (เมื่อติดตั้งลงหน้าจอหลัก)
- **Backend กลาง (aggregator)**: แหล่งข้อมูลหลายแห่งไม่รองรับ CORS, มี rate limit หรือต้องใช้ API key — ต้องดึงผ่านเซิร์ฟเวอร์ของเรา และช่วยลดภาระต่อระบบต้นทาง
- **PostGIS**: ค้นหา "สถานี/กล้อง/ประตูน้ำใกล้ฉันในรัศมี X กม." และตัดตามเขต/อำเภอได้ง่าย
- **MapLibre GL**: โอเพนซอร์ส ไม่ผูกค่าลิขสิทธิ์ ใช้ร่วมกับแผนที่ฐาน OSM หรือผู้ให้บริการแผนที่ไทยได้

## 4. โมเดลข้อมูลกลาง (ร่าง)

```ts
Station     { id, source, type: 'water_level'|'rain', name_th, geom, district, province }
Reading     { station_id, observed_at, value, unit, status: 'normal'|'watch'|'warning'|'critical' }
Floodgate   { id, source, name_th, geom, canal, kind: 'gate'|'pump_station' }
GateStatus  { floodgate_id, observed_at, open_state, upstream_level, downstream_level, pump_rate }
Camera      { id, source, name_th, geom, road, snapshot_url, stream_url?, license_note }
FloodPoint  { id, source, geom, reported_at, depth_cm?, passable_by?: 'car'|'pickup'|'none' }
Alert       { id, level, area, message_th, created_at, related_ids[] }
```

ทุกเรคคอร์ดเก็บ `source` และ `observed_at` เพื่อแสดง **ที่มาและเวลาของข้อมูล** ให้ผู้ใช้เห็นเสมอ

## 5. ฟีเจอร์หลักของแอป

### MVP
- แผนที่รวม พร้อมตัวกรองชั้นข้อมูล (น้ำ / CCTV / ประตูน้ำ / พื้นที่ท่วม)
- สีหมุดตามระดับความเสี่ยง (ปกติ / เฝ้าระวัง / เตือนภัย / วิกฤต)
- หน้ารายละเอียดสถานี: ค่าปัจจุบัน + กราฟย้อนหลัง 24 ชม. / 7 วัน
- หน้ารายละเอียดกล้อง: ภาพนิ่งล่าสุด (รีเฟรชอัตโนมัติ) + เวลาที่ถ่าย
- หน้าประตูระบายน้ำ: สถานะเปิด-ปิด ระดับน้ำหน้า-หลังประตู
- "ใกล้ฉัน": ใช้ GPS แสดงจุดที่ใกล้ที่สุด
- ใช้งาน offline: แสดงข้อมูลชุดล่าสุดพร้อมป้าย "ข้อมูล ณ เวลา ..."
- รองรับภาษาไทย/อังกฤษ

### เฟสถัดไป
- บันทึกจุดที่ติดตาม (บ้าน/ที่ทำงาน/เส้นทางประจำ) + แจ้งเตือน Web Push เมื่อเกินเกณฑ์
- ตรวจเส้นทาง: ซ้อนเส้นทางเดินรถกับจุดน้ำท่วมขังและกล้องตลอดเส้นทาง
- Dashboard วิเคราะห์ข้อมูล (ฝนสะสม vs ระดับน้ำ, จุดท่วมซ้ำ, เวลาระบายน้ำ)
- ต่อยอดการพยากรณ์ระยะสั้นจากข้อมูลย้อนหลัง (nowcasting)

| เฟส | ระยะเวลา (ประมาณ) | งานหลัก | ผลลัพธ์ |

| 2. MVP ข้อมูลน้ำ | 3 สัปดาห์ | Adapter ThaiWater + กทม., แผนที่, หน้ารายละเอียด, offline | ดูระดับน้ำ/ฝน/จุดท่วมบนแผนที่ได้ |

| 4. CCTV | 2–3 สัปดาห์ | CCTV proxy, cache ภาพนิ่ง, (ถ้าได้รับอนุญาต) HLS | ชั้นข้อมูลกล้องพร้อมภาพล่าสุด |
| 5. แจ้งเตือน | 2 สัปดาห์ | กฎเกณฑ์เตือนภัย, Web Push, จุดที่ติดตาม | แจ้งเตือนตามพื้นที่ |
| 6. ทดสอบและเปิดใช้ | 2 สัปดาห์ | Load test ช่วงฝนตกหนัก, ทดสอบบนอุปกรณ์จริง, Lighthouse PWA audit | เปิดใช้งาน (Beta) |

## 7. ข้อพิจารณาด้านเทคนิคและความเสี่ยง

- **ความน่าเชื่อถือของข้อมูล**: แสดงเวลาและแหล่งที่มาทุกค่า, ทำเครื่องหมาย "ข้อมูลเก่า" หากเกินรอบอัปเดต, ใส่ข้อความว่าเป็นข้อมูลประกอบ ไม่ใช่ประกาศทางการ
- **ต้นทางล่ม / เปลี่ยนรูปแบบ**: Adapter แยกต่อแหล่ง มี health check และแจ้งเตือนทีมพัฒนาเมื่อดึงข้อมูลล้มเหลว
- **โหลดสูงช่วงน้ำท่วม**: ใช้ CDN cache สำหรับ API ค่าล่าสุด (TTL สั้น), ส่งภาพ CCTV เป็น snapshot แทนสตรีมเป็นค่าเริ่มต้น
- **CCTV และ PDPA**: แสดงเฉพาะกล้องสาธารณะที่ได้รับอนุญาต, ไม่บันทึกวิดีโอย้อนหลังเกินจำเป็น, ความละเอียดภาพพอดูสภาพน้ำ ไม่ใช่ระบุตัวบุคคล
- **Mixed content**: สตรีมต้นทางที่เป็น HTTP/RTSP ต้องผ่าน proxy HTTPS ของเรา
- **iOS**: Web Push ใช้ได้เมื่อผู้ใช้ "เพิ่มไปยังหน้าจอโฮม" แล้วเท่านั้น — ต้องมีหน้าแนะนำวิธีติดตั้ง
- **Accessibility**: สีสถานะต้องมีไอคอน/ข้อความประกอบ ไม่พึ่งสีอย่างเดียว

## 8. โครงสร้าง repository ที่เสนอ

```
/apps
  /web          # PWA (React + Vite + vite-plugin-pwa)
  /api          # API gateway
  /ingest       # workers + adapters ต่อแหล่งข้อมูล
```

## 9. คำถามที่ต้องการคำตอบก่อนเริ่มพัฒนา

1. กลุ่มผู้ใช้หลักคือใคร — ประชาชนทั่วไป, เจ้าหน้าที่หน่วยงาน, หรือภายในองค์กร?
2. มีช่องทาง/ข้อตกลงการใช้ข้อมูลกับ กทม. หรือหน่วยงานใดอยู่แล้วหรือไม่?
3. ต้องการวิดีโอสดจาก CCTV หรือภาพนิ่งรีเฟรชทุก 1–5 นาทีเพียงพอ?
4. ต้องการเพียง "ดูสถานะ" หรือต้องมี "สั่งการ" ประตูระบายน้ำด้วย (ซึ่งกระทบด้านความปลอดภัยและกฎหมายอย่างมาก)?
5. ข้อจำกัดด้านงบประมาณ/โฮสติ้ง (cloud ที่ต้องการ, เซิร์ฟเวอร์ในประเทศ)?
6. ภาษาและเฟรมเวิร์กที่ทีมถนัด (Python หรือ Node.js ฝั่ง backend)?
